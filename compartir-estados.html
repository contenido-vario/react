Paso 6: Compartir Estados (Lifting State Up)

En este sexto paso resolveremos el aislamiento del paso anterior elevando el estado al componente Padre, que es común al resto de componentes (el componente App).

En React, los datos fluyen en una sola dirección (de arriba a abajo). Si el formulario (TodoForm) necesita añadir elementos a la lista (TodoList), el estado de la lista debe vivir en App.

Luego, App le pasa a sus hijos tanto los datos como las funciones callback, poder modificar ese estado mediante Props.

📍Un callback es una función que se pasa como argumento a otra función para que se ejecute más tarde, generalmente cuando se complete una tarea o se produzca un evento.

Conceptos clave del Paso 6:

  1. Pasar callbacks por Props: Un componente Hijo no puede modificar directamente el estado de su Padre. La solución es que el Padre le pase una función (ejemplo: onAgregarTarea) para que el Hijo la invoque cuando ocurra un evento.
  2. Inmutabilidad en React: En React, debemos tratar el estado como leíble pero no modificable directamente. Nunca se ejecuta tareas.push(nueva) directamente. Para actualizar las tareas, se crea un nuevo array usando el operador spread: setTareas([nueva, ...tareas]).
  3. Puntos débiles a resolver: Si se prueba agregar varias tareas y luego se recarga la página (F5), todas las tareas nuevas se pierden. Además, al agregar una tarea hay que hacer clic manualmente en el input para volver a escribir.

Para solucionar la persistencia en FrontEnd y la manipulación del DOM, usaremos las Puertas de Escape en el Paso 7.
